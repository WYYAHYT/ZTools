# 平台支持范围

- Status: accepted
- Baseline: 0.1
- Last updated: 2026-08-21

## 一等目标平台

ZTools vNext 从设计和测试起把以下环境作为一等平台：

- Windows：具体最低版本在首个发布计划中确定。
- macOS：具体最低版本与芯片范围在首个发布计划中确定。
- Linux：Ubuntu 26.04 LTS，GNOME 默认桌面，原生 Wayland 会话。

“一等”表示共享产品语义、设计评审和发布门禁，不表示每项系统能力在三个平台拥有相同实现或都可无条件提供。

Gate 1 使用的具体 CPU、CI runner 和工具版本见 [ENGINEERING_BASELINE.md](ENGINEERING_BASELINE.md)。工程验证基线不自动构成最终最低系统版本或公开支持承诺。

## Ubuntu 首阶段范围

- 只承诺 Ubuntu 26.04 默认 GNOME Wayland 组合。
- X11/XWayland 可以作为实现细节存在，不作为绕过 Wayland 安全模型的产品方案。
- KDE Plasma、wlroots 合成器、其他发行版和旧 Ubuntu 版本可以被社区试用，但在专门 ADR 扩大范围前不进入发布门禁。
- Ubuntu 发布格式以 `.deb` 为主、AppImage 为辅；最终打包、更新和签名策略在发布阶段确定。

## 支持等级

| 等级 | 定义 |
| --- | --- |
| Supported | 进入自动化与人工发布门禁，阻断性回归会阻止发布。 |
| Preview | 有意支持但尚未达到稳定门禁，限制必须公开。 |
| Community | 可能运行，但项目不承诺测试、修复时限或完整能力。 |
| Unsupported | 已知不在设计范围或无法满足安全/质量要求。 |

首个公开版本前必须把具体操作系统版本、架构、桌面会话和安装格式映射到这些等级。

## 功能完整性的表达

平台支持不使用一个笼统的“支持/不支持”标志。根据已接受的 [ADR-0011](adr/0011-multidimensional-capability-state.md)，每项 Capability 分别报告实现支持、外部依赖、系统授权、运行健康和调用者 Permission。UI 必须说明：

- 缺少什么条件。
- 为什么需要该条件。
- 用户可以采取什么操作。
- 拒绝或不安装后仍可使用哪些功能。

核心搜索、插件管理、设置和安全运行时不能因一个可选平台能力缺失而不可用。

## Wayland 完整体验

Portal 与标准 D-Bus 能力是 Ubuntu 设计的基础路径。根据 [ADR-0007](adr/0007-gnome-wayland-integration.md)，全局召回、先前应用焦点、窗口发现等标准接口无法安全提供的高价值能力，可以依赖用户明确安装和启用的官方 GNOME Shell 扩展。

该策略必须满足：

- 不绕过系统授权。
- 无扩展时提供可理解的降级路径。
- 不把 GNOME 私有实现泄漏为跨平台插件 API。
- 不把未验证能力宣传为 Ubuntu 已支持功能。
- 扩展缺失、禁用、崩溃或版本不兼容时，核心产品继续工作并报告明确状态。

## 发布门禁

每个 Supported 平台至少验证：

- 安装、首次启动、升级和卸载。
- 主窗口召回、隐藏、多显示器、缩放和焦点行为。
- 搜索、动作、插件安装与 Secure Runtime 隔离。
- 权限允许、拒绝、撤销和平台依赖缺失。
- 崩溃恢复、单实例、休眠唤醒和系统会话退出。
- 数据目录隔离、迁移、备份/恢复边界和日志脱敏。
- 平台打包签名、完整性和更新失败恢复。

Ubuntu 还需要在真实 GNOME Wayland 会话验证 Portal 父窗口、系统授权 UI、D-Bus 服务缺失、PipeWire 会话清理以及扩展存在/缺失两种路径（若采用扩展）。

## 扩大支持范围

新增 Linux 桌面环境、发行版、显示协议或 CPU 架构会增加 Adapter、测试矩阵、打包和支持成本，属于 Level 2；若改变一等平台承诺则属于 Level 3。必须有 ADR 和可持续的发布门禁资源后才能承诺。
