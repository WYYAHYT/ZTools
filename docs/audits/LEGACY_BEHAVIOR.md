# 旧 ZTools 只读行为审计

- Status: draft
- Progress: not-started
- Required before: Gate 2 implementation
- Audit owner: unassigned
- Source: `/home/void/work/projects/ZTools` at an explicitly recorded commit

本审计只提取旧项目知识，不为复制旧架构提供授权。开始审计时必须记录旧项目 commit，并保持旧工作区只读。

## 用户可见行为清单

待按“触发条件、用户动作、可见结果、平台差异、失败语义、证据位置”登记主窗口、搜索、动作、插件和设置行为。

## 代表性旧插件 API 使用

选择具有代表性的插件样本，统计实际使用的 API、调用频率、同步假设、平台假设、权限需求和迁移难度。不运行不可信插件代码进行分析。

## 失败案例目录

记录旧项目中已知的竞态、崩溃、安全回退、焦点问题、Wayland 限制、数据损坏和难以测试区域，并把每项映射到 vNext 的控制或明确不处理决定。

## 数据迁移样本

收集脱敏、最小化的数据格式样本和边界情况，记录所有权、版本、隐私与预期转换。vNext 不直接读取旧内部数据库；样本只用于版本化导入器设计和测试。

## 可复用纯算法候选

只有输入输出明确、无 Electron/平台/全局状态依赖且能独立测试的算法可以列为候选。每项必须说明为何迁入优于重写，并先适配 vNext 类型和测试。

## 明确放弃的旧行为

登记因安全、平台限制、产品范围或维护成本而不保留的行为，并说明替代体验或用户沟通。

## 禁止复制清单

- 大型 Manager 和全局单例互调。
- preload 与裸 IPC 注册结构。
- 旧插件权限和内部特权插件模型。
- 业务层平台条件分支。
- 关闭 sandbox、context isolation 或 web security 的配置。

## 完成条件

- 审计来源 commit 和样本范围明确。
- Gate 2 用户旅程均能追溯到新产品决定、旧行为证据或明确的新设计。
- 所有迁入候选经过新边界评审，未复制旧项目耦合。
- 产品负责人确认明确放弃项。
